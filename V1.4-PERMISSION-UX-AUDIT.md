# ScalAI — Audit UX des permissions V1.4

## Règle validée
Une permission ne doit pas être demandée à chaque action lorsque l'utilisateur a déjà accordé **« Autoriser pour la session »** pour la même capacité, le même agent et le même workspace.

### Portées de session
- `agent-run` : exécution de l'agent et accès aux credentials prévus pour cet agent.
- `file-ops` : opérations fichiers dans le workspace.
- `browser` : à utiliser pour les capacités navigateur lorsqu'elles sont branchées au système de permissions.

La décision de session reste en mémoire uniquement et est liée au triplet **workspace + agent + capacité**. Elle n'est donc pas liée à une commande exacte ni à un `cwd` exact.

### Comportement
- **Autoriser une fois** : une seule action, aucun grant persistant.
- **Autoriser pour la session** : pas de nouvelle demande pour les actions normales relevant de la même capacité dans le même workspace avec le même agent.
- **Refuser** : l'action est bloquée.
- Un changement de workspace, d'agent ou de capacité sort du grant et peut provoquer une nouvelle demande.
- Une action hors workspace reste bloquée indépendamment du grant.
