# ScalAI V1.8 — Distribution Hardening

## Objectif
Préparer le projet pour une vraie distribution sans rendre GitHub obligatoire au fonctionnement de l'application.

## Principes
- GitHub est un outil de dépôt/CI/release, pas une dépendance runtime.
- Aucun token GitHub n'est embarqué dans ScalAI.
- Les URL du dépôt et du site sont configurables via `SCALAI_REPO_URL` et `SCALAI_SITE_URL`.
- La vérification des mises à jour reste désactivée tant qu'aucun feed `SCALAI_UPDATE_URL` n'est configuré.
- La télémétrie reste désactivée par défaut ; `SCALAI_PING_URL` est nécessaire pour activer un endpoint.
- Les éléments d'interface qui dépendent d'un site/repo externe ne pointent plus vers l'infrastructure de Nami.

## macOS
Le packaging réel nécessite un runner macOS. Cette version prépare la configuration ; elle ne prétend pas avoir produit ou validé un `.app` macOS dans l'environnement Linux actuel.

## Avant publication
1. Créer le dépôt GitHub officiel ScalAI.
2. Définir `SCALAI_REPO_URL` / `SCALAI_SITE_URL` dans l'environnement de build si nécessaire.
3. Configurer la signature Developer ID et la notarisation Apple dans les secrets CI.
4. Lancer le workflow macOS.
5. Vérifier le `.app`, le DMG, le ZIP et les métadonnées de mise à jour sur un vrai Mac.
