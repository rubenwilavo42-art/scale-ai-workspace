# ScalAI V1.9 — Packaging macOS & signature

## Identité d’édition

- Produit : ScalAI
- Version : 1.9.0
- Signature éditoriale demandée : `sacalai.vatsk.rub`
- Auteur npm : `sacalai.vatsk.rub`
- Copyright bundle : `Copyright © 2026 sacalai.vatsk.rub`
- Mention visible dans le menu/About : `Conçu par sacalai.vatsk.rub`

La signature éditoriale est distincte de l’identité de signature cryptographique Apple. `sacalai.vatsk.rub` n’est pas un Developer ID Apple et ne doit jamais être placé dans `CSC_LINK`, les certificats, les Team IDs ou les identifiants Apple.

## Packaging prévu

- macOS 14 runner pour CI
- Apple Silicon : arm64
- Intel : x64
- `.app`
- `.dmg`
- `.zip` pour les mises à jour
- Hardened Runtime
- Developer ID Application via `CSC_LINK`
- Notarisation Apple via App Store Connect API key
- Validation `codesign`, `spctl` et `stapler`

## Règle importante

Aucun secret Apple n’est embarqué dans ScalAI. Les certificats et clés sont fournis uniquement au runner de release via GitHub Actions Secrets et supprimés à la fin du job.

## État de validation

Le workflow est préparé pour une vraie machine macOS, mais cette archive n’affirme pas que le build signé/notarisé a déjà été exécuté. Cette validation doit être faite sur le runner macOS avec les secrets Apple réels.

## V2.0 — validation CI

Le workflow CI macOS construit maintenant une version de review non signée sur un runner macOS 14, en arm64 et x64, puis publie les DMG/ZIP comme artefacts GitHub Actions. Cela valide le packaging réel sans nécessiter de certificat Apple.

La release de production reste séparée : elle exige les secrets Developer ID et App Store Connect avant de construire et publier.
